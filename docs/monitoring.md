# NyxGuard Manager 5.0.17 monitoring

Monitoring is optional. In Settings → Integrations, create a named integration and save its full token when it is shown once. Existing integration tokens, enable/disable controls, rotation, renaming and last-scrape activity remain available. In Settings → Grafana, the Manager host is prefilled. Paste the saved full token into the token field to generate the scrape configuration; a masked token preview cannot authenticate. The field stays in component memory and does not change saved tokens. Do not put tokens in public dashboards, source or screenshots.

The native endpoint remains `GET /api/integrations/metrics`; the existing `X-Integration-Token` transport and accepted wizard configuration remain supported. Keep internal port 3000 private. The generated self-signed HTTPS example retains `insecure_skip_verify: true`. Existing CA-verified configurations should keep their verification settings. No certificate or authentication redesign is required.

Use the existing Prometheus datasource and download the official JSON in Settings → Grafana. The same versioned file is in [monitoring/grafana/nyxguard-main.json](../monitoring/grafana/nyxguard-main.json). Select the Prometheus datasource, application job and Manager instance. Optional Node Exporter uses its own job selector and the same instance label; missing host metrics remain unavailable. The dashboard preserves UID `nyxguard-main` and all 58 entry IDs: eight groups, 49 data panels and one concise coverage guide. Previous text describing 53 panels did not match the shipped v5.0.16 JSON.

Use the seven duration shortcuts/global time picker: **1D, 2D, 7D, 14D, 30D, 60D and 90D**. These represent elapsed 24-hour multiples, including across daylight-saving changes. There is no independent visible rolling-window selector. Unsupported durations are unavailable. Traffic additionally retains legacy 1h/180d windows. Current-state panels show snapshots, and fixed 24h/30d reference panels keep explicit labels.

Historical cards show exact counts of retained observations within UTC `[start,end)` intervals ending at the same closed five-minute evaluation cutoff. That cutoff is not a verified committed ingestion watermark. `nyxguard_history_evaluation_cutoff_seconds` identifies it; `nyxguard_metrics_generated_timestamp_seconds` identifies generation; the difference describes evaluation age, not ingestion completeness. `nyxguard_history_source_up` means a source query succeeded; enforcement additionally requires the existing fresh collector heartbeat. Committed-cutoff and ingestion-freshness availability flags remain zero where durable provenance is unavailable. `nyxguard_history_complete=0` explicitly marks unverified continuity. No zero timestamp is invented for an unknown watermark.

`nyxguard_history_window_days` maps the seven native durations. Existing optional adapters continue to pass it through and may retain their legacy four-window `nyxguard_monitoring_window_days` mapping; the two names do not collide. Legacy gauge metric names and preferred gauge aliases remain compatible. Never apply `increase()` or `rate()` to rolling gauges, add overlapping window values, or sum daily distinct-IP counts. Missing/stale/failed sources show unavailable; genuine measured zero remains zero.

Attack detections and exact trailing distinct attackers describe retained occurrence rows. Automatic-ban observations describe retained automatic deny rules; deleted rules cannot be reconstructed. Country/custom-WAF enforcement remains subject to its configured 30-day retention and row cap. Portal observations retain their signed-session rejection provenance and follow Event Center retention. Per-application traffic sums non-overlapping closed source buckets. Configured privacy/retention policies are preserved; selecting 90D does not establish complete 90-day history.

For an existing dashboard, export a backup and preserve customizations first. Import the new JSON into a copy for comparison, or intentionally update UID `nyxguard-main` after reviewing differences. Select the existing datasource; preserve credentials. For file-provisioned dashboards, the monitoring administrator must back up and update the authoritative provisioning file using their own drift/rollback procedure. Updating Manager or publishing a release never changes an external Grafana server automatically.

Prometheus sample retention is separate from the Manager's exported 90D observations. Prometheus defaults can retain fewer than 90 days. A configuration such as `--storage.tsdb.retention.time=100d` is an optional operational choice after storage, WAL/head, compaction and backup planning. Preserve the current TSDB and configuration. Never recreate the TSDB or delete WAL merely to change retention. Longer retention does not reconstruct expired samples or missing native observations. External maintenance requires its own authorized procedure.

The existing optional [mTLS adapter and provisioning generator](../release-source/5.0.14/final/monitoring/) remain usable with this release. Preserve existing TLS credentials, verification and the native integration token. When using that historical generator, replace its generated dashboard with the current official JSON linked above and select the existing datasource. No additional monitoring service is required for ordinary Manager operation.
