# Operational diagnostics contract (5.0.11)

The shared service in `internal/operational-diagnostics.mjs` records authenticated API failures through the application error handler. The existing administrator-only Professional Support routes expose grouped recent problems and bundle export. Existing support entitlements and permissions are preserved. Certificate renewal timers, Traffic Monitor operational failures, and Update Manager failed-job completion use the same service. The supported host updater writes a bounded, allowlisted recovery summary into the existing Manager data mount; 5.0.11 imports it into the application database.

## Storage and fields

The additive `20261011000000_operational_diagnostics.js` migration creates `operational_diagnostic` in the existing application database. Its primary key is the UUID diagnostic event ID; indexed fields are UTC ISO `created_on` and a SHA-256 grouping fingerprint. `payload` contains selected safe JSON, never raw command output or stack traces.

Events include event ID, UTC timestamp, severity, component, operation, summary, structured code, classified safe cause and cause kind, numeric resource identity, outcome, application-state caveat, correlation UUID, recommended action, runtime version, and optional administrative actor ID. Technical evidence is restricted to named dependency failures, known system/SQL error codes, and classified stage metadata. Cause kinds distinguish reported errors from unconfirmed generic failures. An operation's partial-completion outcome is preserved when its service establishes that state. Recovery status is reported as recovered only when the host reports a verified rollback.

Retention defaults to 30 days and is configurable with `NYXGUARD_DIAGNOSTIC_RETENTION_DAYS`, bounded to 1–90 days. Recording and host ingestion prune expired events and excess rows beyond 10,000. Failed persistence emits only a fixed fallback warning and event ID/code; it must not replace the primary operation error. During database unavailability, successful durable recording cannot be guaranteed; the safe fallback is container logging.

The Recent problems API accepts existing 15-minute, 60-minute, and 24-hour windows, returns 20 grouped rows per page, and retains counts and first/last timestamps within the selected window. Known technical evidence participates in grouping. The list remains bounded in the existing panel, with expandable details and Previous/Next controls. Expected authentication denials, missing resources, and security-traffic blocks do not generate diagnostic errors.

Bundles include up to 200 representative operational groups across the configured retention window, health checks and operational status, IDs and latest representative correlation IDs, occurrence counts, and a manifest declaring exclusions and truncation. Source selection and final bundle redaction provide separate boundaries. Repeated groups retain the most recent representative ID; earlier occurrence IDs persist in the database but are not individually exported. Event Center request correlation is not yet shared with diagnostic UUIDs.

## Supported host updater bridge

The updater writes `/data/.nyxguard-operational-updater.json` as `{format:"nyxguard-host-operational-v1",events:[...]}` after recovery is attempted, using atomic fsync/rename. It holds at most 64 events/128 KiB and includes only allowlisted IDs, timestamps, host failure codes, recovery states, stage metadata, and semantic versions. Manager opens the summary without following symlinks, rejects oversized/malformed input, derives fixed safe summaries, and inserts via UUID primary-key conflict ignoring. Replay after process/container recreation cannot create duplicate occurrences.

Allowed host codes are `HOST_UPGRADE_FAILED`, `HOST_BACKUP_FAILED`, and `HOST_RECOVERY_INCOMPLETE`. The failure is imported into 5.0.11 after its Diagnostics API is available. A rollback to an older version cannot gain a new Diagnostics feature; the summary survives for investigation when 5.0.11 is subsequently running.

## Health checks and limitations

Run diagnostics retains existing Manager/database, migrations, Nginx validity, VPN, updater/recovery and licensing observations. It adds separately bounded Certbot executable, Python module, Cloudflare plugin, and certificate-storage read/write permission checks. The storage write check inspects effective access without writing certificate files. Plugin import confirms importability, not live provider authentication. External authority activation and ACME issuance require independent controlled acceptance; no health check contacts or modifies licensing state.

The API handler covers propagated errors for Proxy Hosts, certificates, Access Lists, VPN, rules, WAF, Shieldwall, users, settings and integrations. A service that swallows its error or reports an unsuccessful HTTP result directly may bypass the shared handler unless specifically instrumented. Global auth-bypass master-switch synchronization preserves its final enforcement apply but propagates a partially-completed database failure when app or host metadata synchronization failed; it cannot return HTTP success for that known partial failure. Default-site configuration cleanup is awaited and a rejected configuration propagates an actionable Nginx failure with partial-completion state. Background coverage includes certificate renewal, renewal query/notification failures, Traffic Monitor aggregation/log permission/retention/polling failures, Update Manager job completion, and supported host updater failure/recovery summaries. Expected absent/rotated traffic logs and startup missing-table guards are suppressed. Optional absent VPN status polling remains an availability observation; VPN administrative mutations and tests propagate failures through the shared handler. Uninstrumented background services remain outside this enumerated coverage. Generic errors preserve truthful uncertainty rather than inventing a technical cause.

No production failure injection or publication is authorized. Final runtime, persistence, bundle, and browser acceptance evidence belongs to the private disposable laboratory; unit classification tests alone do not prove external administrative workflows.
