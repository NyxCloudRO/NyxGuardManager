# Optional Prometheus and Grafana integration

Use the existing Settings → Integrations to create an enabled integration. Save the one-time token in `integration-token`, mode 0600. It survives Manager upgrades in the existing database; rotate it in Settings if lost. Settings → Grafana remains the application's Grafana connection; no second application credential registry is introduced.

The native endpoint is `GET /api/integrations/metrics` on internal port 3000 with `X-Integration-Token`. Never publish that internal port or put its token in a URL/dashboard. On a shared private Docker network, the optional adapter calls it using the existing `nyxguard-manager` service alias. Configure `NYXGUARD_NATIVE_METRICS_URL` if the alias differs. A remote native source must use verified HTTPS.

For cross-host scrapes, use the provided optional adapter with mTLS. Supply `server.crt` (with the adapter DNS name in SAN), `server.key`, `ca.crt`, and `integration-token` in a protected directory readable by UID 1000. Keep keys/tokens 0600; no secrets enter images or dashboard files. Use your organization's CA to issue a dedicated client certificate for Prometheus. The adapter accepts only CA-authenticated clients and TLS 1.2 or later. Firewall its explicitly selected private bind address to authorized monitoring hosts. Start it with the provided Compose file after setting the three required environment variables. No Docker socket or application volumes are mounted. This is optional and does not install Grafana/Prometheus for other users.

Run `python3 generate.py --target metrics.example.test:9444 --prometheus-url https://prometheus.example.test --output ./generated` on an administrative workstation. Merge the generated scrape job into the existing Prometheus configuration; do not replace unrelated jobs. Install the client CA/certificate/key at the indicated paths. Run `promtool check config` on the merged configuration, then reload Prometheus using your authorized administrative workflow. Query `up{job="nyxguard"}` and `nyxguard_metrics_source_failures` (expected 1 and 0 respectively); check native generation freshness. An HTTP 503, absent series or source-up 0 is unavailable, never a measured zero.

Import `dashboard.json` through Grafana's existing dashboard import UI and select your datasource, or install `datasource.yml` and `provider.yml` into Grafana's existing provisioning directories with the dashboard at `/etc/grafana/nyxguard-dashboards`. Configure Grafana-to-Prometheus authentication in Grafana's secure datasource settings if required. The generated files intentionally contain no credentials. Select Manager instance, application job and rolling event window. Node panels additionally require a separately installed node_exporter job; assign the same `instance` label as the corresponding Manager or adjust its selector. No host metrics are fabricated when node_exporter is absent. The independent Grafana time picker controls scraped history, which accumulates from actual samples.

The existing dashboard UID `nyxguard-main` and 58 panel IDs remain stable. For existing monitoring adapters, replacing only the application activates corrected contract v1 families without reinstalling the dashboard. Install this portable dashboard once to activate the new dedicated event queries and selectable datasource/job/instance; subsequent Manager upgrades preserve provisioning and credentials. Keep external provisioning under your monitoring server's normal backup/restart policy; the application updater does not need or assume rights to external infrastructure.

Gauge families ending in `_total` are legacy compatibility names. Do not apply `rate` or `increase` to them. Correct gauge aliases without `_total` are supplied by the final exporter; migrate queries at your own pace. Event metrics count retained observations in half-open rolling UTC windows, not lifetime totals. WAF observations retain 30 days. Access Portal Security Rejection events follow configurable Event Center retention (default 180 days). Neither implies complete history, including before instrumentation or following deletion. Normal failed logins, expired sessions, absent cookies, authorized portal skips, upstream 403s and detector-only events are excluded.

The optional adapter reuses the matching hardened Manager image with an explicit Node entrypoint, read-only root filesystem, non-root UID and no Docker socket. It starts only the adapter. Update this optional image with the supported Manager release; preserve its external TLS/token directory. No separate unqualified Node runtime is required.
