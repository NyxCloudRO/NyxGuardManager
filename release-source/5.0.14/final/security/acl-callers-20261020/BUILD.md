# ACL library and file-tool caller corrections

The library input is the complete ACL 2.4.0 source archive included here. Build out of tree using the existing Debian 12 amd64 release toolchain: configure --prefix=/usr --libdir=/usr/lib/x86_64-linux-gnu --disable-static, then make. Retain libacl.so.1 and all legacy symbol versions; four _at APIs and ACL_1.3 are additive. The library's legacy pathname APIs retain their documented symlink semantics. The caller corrections below provide object binding; the version change alone does not establish caller safety.

Coreutils 9.1-1 and tar 1.34+dfsg-1.2+deb12u1 use the original and Debian source archive hashes/URLs in source-inputs.json. Apply each Debian patch series, then overlay the corresponding complete source files included in coreutils/ and tar/. The unified patches provide a review aid; the full overlaid sources, including tar's changed xattrs.h declaration, are authoritative. Configure coreutils out of tree with --prefix=/usr --enable-no-install-program=arch --enable-single-binary=no and FORCE_UNSAFE_CONFIGURE=1, then build src/cp and src/mv. Configure tar out of tree with --prefix=/usr --with-posix-acls --with-xattrs --with-selinux, then make. Use the original system ACL headers while compiling these callers, avoiding GNU tar's known name collision with ACL 2.4 headers. These callers use the preserved library ABI and descriptor-backed procfs references; they require Linux O_PATH and the mounted /proc filesystem used by the application.

cp and cross-device mv retain directory/special-file identities across ACL preservation and pin the creation parent. Regular-file paths retain their existing open descriptors. tar binds ACL reads to the selected object; deferred directory restoration checks the extraction identity before using one pinned descriptor. O_PATH avoids FIFO blocking, device opening and additional read-permission requirements. No failed descriptor acquisition falls back to an untrusted pathname for ACL restoration.

package-callers.py preserves other installed package payloads and maintainer scripts, replaces only cp, mv, tar and libacl, and regenerates md5sums. It expects the qualified filesystem at /previous/release-rootfs and build outputs beneath /work. libacl1 uses the honest upstream version 2.4.0-0nyxguard1 while retaining the pre-existing installed library filename and SONAME for compatibility. coreutils and tar use explicit +nyxguard1 backport package revisions. Private test fixtures, logs and security dispositions are excluded from this release source.

The saved ACL upstream suite records 13 PASS, 2 expected NFS failures and one container device-policy errno mismatch (EPERM instead of ENXIO when opening an unavailable block device). This is not an unconditional full-suite pass. Runtime compatibility and caller acceptance are recorded separately in the release manifest.
