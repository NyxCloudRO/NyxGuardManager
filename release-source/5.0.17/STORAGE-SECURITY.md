# Storage maintenance trust boundaries

The Manager authenticates its existing Bearer session, reloads the enabled administrative user, rejects NyxAgent and read-only principals, checks Settings management permission and validates browser origins for mutation. Integration tokens cannot authorize storage operations. The Unix-socket host broker checks local peer credentials and accepts only fixed inventory, preview and delete actions. Client input cannot specify paths, Docker endpoints, commands or arbitrary image IDs.

The broker pins the installation directory, opens updater members with directory-relative descriptors and NOFOLLOW, rejects special files/hardlinks/untrusted ownership or permissions, checks mount boundaries and updater locks, hashes all manifest payloads during review and confirmation, binds two-minute single-use plans to the actor and full inventory revision, and preserves the newest successful backup targeting the running version. Unknown/corrupt backup provenance prevents deleting that backup and disables image cleanup because its image dependencies cannot be established. Other independently verified historical backups can still be reviewed when the immediate recovery set is verified. Images required by any retained verified-manifest backup or any running/stopped container remain protected. Docker deletion uses an immutable server-resolved identity, force=false and noprune=true. Volumes, caches and unrelated images have no mutation endpoint.

Official host scripts install a small root-owned Python standard-library service. It has no TCP listener, additional application Docker mount or general host-file API. Existing socket exposure for legacy functionality is unchanged. The broker's Docker socket remains root-capable internally; its code and narrow contract are the boundary. Durable host audit intent is fsynced before destruction, then actual success/partial failure is recorded. Application audit records are sanitized and bounded per event. Disk-space changes are observed filesystem deltas and may include concurrent writes. Shared image layers are excluded from uniquely reclaimable estimates where Docker supplies reliable size metadata.

The current conservative policy disables cleanup before the first identifiable verified recovery set. Historical in-app recovery transactions do not automatically qualify as host-updater backups. This preserves recovery rather than guessing eligibility. A crash during directory deletion can leave a partial historical backup; it is then unverifiable and requires manual review. Protected immediate recovery is never selected.

Inventory never waits for optional Docker layer accounting. A single background worker requests image-only disk usage at most once per five minutes; unavailable accounting is shown as unknown. The resource list is scoped to supported repositories plus immutable deployment/recovery identities. All running and stopped container references remain authoritative. Accounting updates do not alter destructive plan identity.

Administrator external-backup override is explicit and defaults off. After confirming an external VM backup, an administrator may review deletion of all local updater backups (including the immediate recovery set) and unused discovered NyxGuard recovery images. A safely pinned backup tree can be removed even when its manifest is unverifiable; the review never claims checksum verification in this mode. Local rollback may consequently become unavailable. All updater locks, pending-operation checks and filesystem identity/link/ownership protections still apply.

Obsolete images held by stopped containers require those exact server-issued container identities to be explicitly selected. Review names every container before its image. The broker rechecks container state immediately before fixed Engine DELETE requests with force=false and v=false; it never removes volumes. Running containers and this deployment’s current Manager, database and VPN services remain protected. A container starting after review invalidates the plan. Override mode is bound to the actor’s expiring single-use plan and recorded in the durable host audit and application audit. Arbitrary container deletion and arbitrary Docker API forwarding remain unavailable.
